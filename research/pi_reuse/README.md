# Pi reuse study

This is the extracted runner for the three-draft, twelve-consumer flake-search study.
The [public report](https://dynamicalsystems.ai/blog/simulator-verified-skill-acquisition)
explains the result. The [evidence package](../../artifacts/evidence/studies/pi-reuse/)
contains the original procedures, outcomes, usage, and frozen provenance.

## Replay the published result

From the repository root, after `uv sync --locked --extra dev --extra simulators`:

```bash
uv run python -m research.pi_reuse.replay
```

Replay uses saved procedures and deterministic simulator cases. It needs no API key,
Pi installation, or inference. Published cases were sealed during the original study;
they are now available for replay, not a hidden test set for new acquisition.

## Run a new comparison

Use Linux with Python 3.12 or 3.13, Node.js, bubblewrap (`bwrap` on PATH with working
user namespaces), and native Pi **0.84.4**. Install Pi with
`npm install -g @earendil-works/pi-coding-agent@0.84.4` and verify `pi --version`.
Set `OPENROUTER_API_KEY` in the environment. `PI_BIN` may name a different executable
path; the runner checks its version. Credentials are never read from local files.

Before generation, prepare a new contract and fresh private scene seeds under ignored
`runs/`, preserving the published parameter regimes and grading rules. Update
`private_hash` to the SHA-256 of the new `sealed-cases.json` and record the new budget
accounting in that contract. Freeze the contract before any generation. The checked-in
`contract.json`, `source.md`, and `extension.ts` preserve the original study inputs.

Use the same directory and contract for every command. For example:

```bash
uv run python research/pi_reuse/run.py --run-dir runs/pi-reuse-new --contract runs/pi-reuse-new/contract.json freeze
uv run python research/pi_reuse/run.py --run-dir runs/pi-reuse-new --contract runs/pi-reuse-new/contract.json run smoke-1
uv run python research/pi_reuse/run.py --run-dir runs/pi-reuse-new --contract runs/pi-reuse-new/contract.json run smoke-2
```

Require both smoke sessions to complete before continuing. Run `draft-1` through
`draft-3`, then `packages before` to preserve all starting packages. Run `repair-1`
through `repair-3`, then `packages after` to preserve every final repair, including
unsuccessful repairs. Run the twelve consumer names in the contract's `order` and
only then run `score`. Each is a subcommand of the same invocation above. Session
receipts, attempts, and raw traces remain under the run directory.

`runtime.py` derives the result from observed completion and applies the existing
instrument verifier. It is study-specific and does not change the production result
interface. The extracted runner records its own freeze; the original study's hashes
remain in the evidence package.

The original acquisition scripts remain in the local study archive. Their hashes and
prompts are preserved in `freeze.json`; the extracted runner is not the exact script
that generated the published procedures. Replay checks every recorded case outcome
and the paired comparison against those procedures. Token counts are recorded usage,
including repeated and cached context, and are not regenerated by simulator replay.
`export.py` generates the allowlisted bundle from that original local archive.
